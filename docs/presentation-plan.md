## 3. 만드는 방법 (선택지)

| 방법 | 좋은 점 | 아쉬운 점 |
|---|---|---|
| **A. 실제 화면 녹화** — OBS Studio(이 PC에 설치됨) 또는 Windows 캡처 도구로 mp4 → GIF 변환 | 진짜 작은 창이 VS Code·젭 위에 떠 있는 모습. 설득력이 가장 큼 | 다시 찍기 번거로움, 두 기기 화면 맞추기 |
| **B. 자동 녹화** — Playwright로 같은 흐름을 매번 똑같이 재생, 영상 저장 → GIF | 몇 번이든 깨끗하게 다시 찍음, 강사·학생 화면 나란히 합성 가능 | 진짜 작은 창이 아니라 원래 탭 미리보기(작은 창 모양 흉내) |

추천: **핵심 장면(GIF-1·3·4·5)은 A**, 화면 설명용(GIF-2·6)은 **B**. 발표에서 “실제 화면”과 “재현 화면”을 표시해 구분한다.

- GIF 변환: 이 PC에 ffmpeg가 없다(2026-10-28 확인). 후보 — ffmpeg 설치, `ffmpeg-static` npm 패키지, ScreenToGif(녹화+편집+GIF 저장 한 번에). 시작할 때 사용자와 고른다.
- GIF 규격(안): 폭 800~960px, 10~15fps, 8초 이하, 장당 5MB 이하. 개인정보·실제 질문·참여 코드는 가상 데이터로(저장소 공개 규칙과 동일).

## 4. PPT로 만들 때 주의

- PowerPoint는 GIF가 움직이지만 **PDF로 내보내면 멈춘 그림**이 된다. PDF 제출본에는 대표 장면 정지 사진 + 시연 영상 링크를 넣는다.
- 형식 후보: PowerPoint 파일(.pptx)에 GIF 삽입, 또는 웹 슬라이드. 시작할 때 사용자와 고른다.
- 시연 영상(1~3분)은 GIF를 이어 붙이지 말고 실제 두 기기 흐름을 한 번에 녹화하는 편이 PRD 의도(“실제 두 기기 시연”)에 맞다.

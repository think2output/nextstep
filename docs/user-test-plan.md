# 사용자 비교 시험 계획 (DEV09, PRD 20장)

> 일정: 2026-10-29 (예정). 강사 역할: 사용자(PM). 참가자: 동기 4~5명(수강생 역할).
> 목적: 발표 4번 “평가 리포트”의 **전후 비교**. A(지금 쓰는 채팅 응답) vs B(작은 창 응답).
> 결과는 `docs/test-report.md`에 적고, 이 문서는 진행 방법만 둔다. 이름·질문 본문은 저장소에 넣지 않는다(공개 저장소).

## 1. 한눈에

| 항목 | 내용 |
|---|---|
| 시간 | 약 40분 (준비 5 · 전반 12 · 후반 12 · 질문 과업 5 · 설문 5) |
| 조건 | A: 채팅에 답하기 (평소처럼 이모지·숫자 허용, 타이핑 강제 안 함) / B: 작은 창에서 클릭 |
| 순서 | 1조는 A→B, 2조는 B→A (PRD 20.2 순서 번갈아). 같은 시간에 두 조가 서로 다른 방식으로 답한다 |
| 요청 | 반마다 6회: 준비·이해·진행 각 2회 (PRD 20.3). 전체 12회 |
| 알림 | 두 조 모두 **강사의 말**로 알게 한다(같은 신호). 강사는 말하는 순간 작은 창 요청도 보낸다 |
| 재는 것 | 응답 시간, 응답 여부(15초 넘으면 미응답), 화면 전환, 설문 |

알림을 말로 똑같이 주는 이유: 두 방식의 차이를 “응답하는 수고”로 좁히기 위해서다. 그래서 이 시험은 작은 창이 **알아채기**를 돕는 효과는 재지 않는다(발표에 한계로 적는다).

## 2. 사람과 조

| 코드 | 조 | 전반 | 후반 |
|---|---|---|---|
| P1 | 1조 | A 채팅 | B 작은 창 |
| P2 | 1조 | A 채팅 | B 작은 창 |
| P3 | 2조 | B 작은 창 | A 채팅 |
| P4 | 2조 | B 작은 창 | A 채팅 |
| P5 (있으면) | 1조 | A 채팅 | B 작은 창 |

- 코드 P1~P5는 **방에 들어온 순서**다. 강사가 “P1 들어와 주세요 → 들어왔어요 → P2 …” 순서로 한 명씩 입장시킨다. 서버 기록을 사람과 맞추는 유일한 방법이다(앱은 이름을 받지 않음).
- 이름 ↔ 코드 대응표는 강사 개인 메모에만 둔다. 저장소·발표 자료에 넣지 않는다.

## 3. 준비물 (시험 전날·직전)

- [ ] 참가자: 노트북, **Chrome 최신**(Edge·Safari는 작은 창 미확인), VS Code, 젭(또는 쓰는 채팅) 접속
- [ ] 강사: 배포 주소 https://nextstep-smoky.vercel.app 에서 방 만들기(운영자 코드), 참여 링크 복사
- [ ] 강사 화면 **녹화**(소리 포함): 강사 작은 창 + 채팅창이 같이 보이게. OBS 또는 Windows 캡처 도구(Win+Alt+R). A 응답 시간을 여기서 잰다
- [ ] 실습 과제 2개(난이도 같게): 예) 전반 “배열 합 함수 따라 치기”, 후반 “문자열 뒤집기 함수 따라 치기”
- [ ] 설문 폼(아래 6장) — 구글 폼 등
- [ ] 시험 끝난 뒤 **24시간 안에** B 시간 뽑기(방 종료 24시간 뒤 데이터가 지워짐)

## 4. 진행 순서와 강사 대본

### 0~5분 준비

> 오늘 도와줘서 고마워요. 수업 중에 강사가 “이해했나요?”를 물을 때 답하는 두 가지 방법을 비교해요.
> 이름이나 개인정보는 기록하지 않고 P1, P2 같은 코드로만 정리해요. 질문 내용도 통계에 넣지 않아요. 괜찮으면 시작할게요. (동의 확인)
> 링크를 보낼게요. 제가 부르는 순서대로 한 명씩 들어와 주세요. P1님 → 들어왔나요? → P2님 …
> 2조(P3·P4)는 들어오면 ‘작은 창 띄우기’를 눌러서 VS Code 위 잘 보이는 곳에 둬 주세요.
> 1조는 작은 창을 띄우지 말고, 대답은 채팅으로 해 주세요.

- 모두 VS Code를 앞에 두고 실습 과제를 시작한다. 젭·채팅은 평소 수업처럼 뒤에 둔다.

### 5~17분 전반 (요청 6회, 약 2분 간격)

매번 강사는 **말하면서 동시에 작은 창에서 요청을 보낸다**:

| 회 | 강사가 하는 말 | 작은 창 |
|---|---|---|
| 1 | “준비됐으면 알려 주세요” | 준비 확인 |
| 2 | “여기까지 이해했으면 알려 주세요” | 이해 확인 |
| 3 | “다음으로 넘어가도 될까요?” | 진행 확인 |
| 4 | “이해했으면 알려 주세요. **이번엔 처음에 ‘다시 설명’을 고르고, 바로 ‘이해했어요’로 바꿔 주세요**” | 이해 확인 (PRD 20.3 ‘대기→긍정’ 바꾸기) |
| 5 | “준비됐으면 알려 주세요” | 준비 확인 |
| 6 | “다음으로 넘어가도 될까요?” | 진행 확인 |

- 1조(A): 채팅에 답한다. 예) 👍 / 1 = 긍정, 🙋 / 2 = 대기. 평소 쓰는 표시 그대로.
- 2조(B): 작은 창에서 클릭.
- 각 요청은 **15초** 뒤 강사가 ‘확인 종료’. 15초 안에 없으면 미응답으로 센다.

### 17~29분 후반 (바꿔서)

> 이제 바꿔요. 1조는 작은 창을 띄워 주세요. 2조는 작은 창을 닫고 채팅으로 답해 주세요.

같은 표 1~6회를 같은 순서로 다시. 실습 과제는 두 번째 과제로.

### 29~34분 질문 과업 (모두 작은 창)

> 모두 작은 창에서 질문 탭을 열어 주세요.
> 1) 실습하다 궁금했던 걸 익명으로 하나 남겨 주세요.
> 2) 다른 사람 질문 하나에 ‘저도 궁금해요(+)’를 눌렀다가, 한 번 더 눌러 취소해 주세요.

- 강사: 질문 목록에서 공감 많은 순으로 보고, 2개를 ‘답변 완료’로 처리. (PRD 20.3의 “20건 중 미답변 5건 찾기”는 참가자 수가 적어 이번엔 생략 — 결과 보고에 적는다)

### 34~39분 설문 → 방 종료

## 5. 기록표 (강사가 녹화를 보며 채움)

A 시간: 녹화에서 **강사가 작은 창 ‘보내기’를 누른 순간** → 그 사람의 **채팅이 강사 화면에 뜬 순간**(초, 소수 1자리).
B 시간: `npm run usertest:times -- <참여코드>` 가 서버 시각으로 계산(요청 시작 → 첫 응답).
- 모두 한 방에 있으므로 작은 창 요청은 A 쪽 사람에게도 간다. 스크립트 결과에서 **그 사람이 B였던 회차만** 쓴다(전반 1~6회는 P3·P4, 후반 7~12회는 P1·P2·P5). A 쪽 사람의 ‘no_response’는 무시.
- 강사 작은 창의 “N/M명 응답”도 A 쪽 사람을 포함해 세므로, 시험 중에는 M이 참가자 전체 수로 보인다(정상).

| 참가자 | 조건 | 회 | 시간(초) | 결과(ok/미응답) | 화면 전환·관찰 메모 |
|---|---|---|---|---|---|
| P1 | A | 1 | | | |
| … | | | | | |

- 두 방식의 시간은 각자 한 시계(A: 녹화, B: 서버)로만 잰다. 서로 다른 기기 시계를 섞지 않는다(PRD 18).
- 차이: A에는 채팅이 강사 화면에 뜨기까지의 전달 시간이, B에는 서버 저장 시점까지가 들어간다. 둘 다 1초 안팎이라 결과 해석에 함께 적는다.

## 6. 설문 (5문항, 끝나고 바로)

1. 어느 쪽이 응답하기 편했나요? (A 채팅 / B 작은 창 / 비슷함)
2. A 채팅으로 답할 때 실습 흐름이 끊긴 정도 (1 전혀 안 끊김 ~ 5 많이 끊김)
3. B 작은 창으로 답할 때 실습 흐름이 끊긴 정도 (1 ~ 5)
4. 작은 창이 실습 화면을 가려서 방해됐나요? (1 전혀 아님 ~ 5 많이 방해)
5. ‘다시 설명’(모르겠어요)을 누르기 부담됐나요? A / B 각각 (1 ~ 5) + 자유 의견 한 줄

## 7. 계산 (PRD 20.5)

- 참가자마다 조건별 응답 시간 **중앙값**.
- 개인 개선율 = (A 중앙값 − B 중앙값) / A 중앙값 × 100.
- 전체 = 개인 개선율의 중앙값과 범위(최소~최대).
- 15초 넘은 응답은 시간 표본에서 빼고, 미응답·실패 수는 조건별로 따로 보고.
- 표본이 4~5명이라 통계적 일반화·학습 효과 개선은 주장하지 않는다. 클릭이 실제 이해도를 잰다고도 주장하지 않는다.
- 불리한 결과도 그대로 발표한다(PRD 20.6). 예: 시간이 줄었는데 미응답이 늘면 “알림 인지” 문제로 해석.

## 8. 시험 뒤 할 일

1. 당일: `npm run usertest:times -- <참여코드>` → B 결과를 기록표로.
2. 녹화로 A 시간 채우기.
3. `docs/test-report.md`에 결과(표본 수·중앙값·개선율·미응답·설문 요약·관찰), 이 계획에서 바꾼 점·생략한 점.
4. 발표 4번 장 표·그래프.
